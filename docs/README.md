# Documentation Structure\n\nAll project documentation is organized by concern in dedicated folders.\n\n## Desktop System Documentation\n\n**Location:** `docs/DESKTOP/`\n\nComplete documentation for the E2B Desktop Sandbox integration.\n\n### Files\n\n| File | Purpose | Audience |\n|------|---------|----------|\n| [README.md](./DESKTOP/README.md) | Overview and quick start | Everyone |\n| [ARCHITECTURE.md](./DESKTOP/ARCHITECTURE.md) | System design and components | Developers |\n| [TOOLS.md](./DESKTOP/TOOLS.md) | Computer-use tools reference | Developers, AI engineers |\n| [AGENT.md](./DESKTOP/AGENT.md) | Agent capabilities and workflows | AI engineers, product |\n| [API.md](./DESKTOP/API.md) | API endpoints and integration | Backend developers |\n| [GAPS.md](./DESKTOP/GAPS.md) | Missing features and roadmap | Product, developers |\n| [SETUP.md](./DESKTOP/SETUP.md) | Configuration and deployment | DevOps, developers |\n\n### Quick Navigation\n\n**I want to...**\n- Understand the system → [ARCHITECTURE.md](./DESKTOP/ARCHITECTURE.md)\n- Use the tools → [TOOLS.md](./DESKTOP/TOOLS.md)\n- Build with the agent → [AGENT.md](./DESKTOP/AGENT.md)\n- Integrate the API → [API.md](./DESKTOP/API.md)\n- See what's missing → [GAPS.md](./DESKTOP/GAPS.md)\n- Set up locally → [SETUP.md](./DESKTOP/SETUP.md)\n\n## Documentation Principles\n\n### Separation of Concerns\n\nEach document focuses on a single concern:\n- **ARCHITECTURE** — How components fit together\n- **TOOLS** — What the agent can do\n- **AGENT** — How the agent works\n- **API** — How to integrate\n- **GAPS** — What's missing\n- **SETUP** — How to configure\n\n### Audience-Specific\n\nEach document targets specific roles:\n- **Developers** — Implementation details, code examples\n- **AI Engineers** — Agent capabilities, workflows\n- **DevOps** — Configuration, deployment\n- **Product** — Features, roadmap\n- **Everyone** — Quick start, overview\n\n### Actionable\n\nEach document includes:\n- Clear examples\n- Code snippets\n- Step-by-step guides\n- Troubleshooting\n- Links to related docs\n\n## Adding Documentation\n\nWhen adding new features:\n\n1. **Architecture changes** → Update `ARCHITECTURE.md`\n2. **New tools** → Update `TOOLS.md`\n3. **Agent changes** → Update `AGENT.md`\n4. **API changes** → Update `API.md`\n5. **Missing features** → Update `GAPS.md`\n6. **Setup changes** → Update `SETUP.md`\n\n## Maintenance\n\nKeep documentation in sync with code:\n- Review on every PR\n- Update examples when code changes\n- Keep links current\n- Remove outdated sections\n"
